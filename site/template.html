Pick ONE hostname. Never paste the whole list. Hostnames marked DoH only do not work in Android Private DNS.

      📱 Android — Private DNS (DoT)
      

        
    
          
  1. Settings → Network & internet → Private DNS.
    2. 
          
  2. Some phones: Settings → Connections → More connection settings → Private DNS.
    3. 
          
  3. Choose Private DNS provider hostname.
    4. 
          
  4. Paste one DoT hostname, e.g. dns.adguard-dns.com, and tap Save.
    5. 
        

        
DoH-only hostnames (the ones tagged DoH) will show “can't be resolved” here — that is expected.

      

    


    

      🍎 iPhone / iPad — DNS profile (DoH)
      

        
iOS has no Private DNS field. Use a DoH/DoT profile app such as DNSecure (free, open source) or install a .mobileconfig profile. Paste the endpoint's DoH URL, for example https://dns.adguard-dns.com/dns-query.

        
ShortsGuard works in Safari through the userscript manager Userscripts (App Store) — install guard/shorts-guard.user.js.

      

    


    

      🪟 Windows 11 — DNS over HTTPS
      

        
    
          
  1. Settings → Network & internet → your connection → DNS server assignment → Edit.
    2. 
          
  2. Manual → enable IPv4 → Preferred DNS 1.1.1.1, Alternate 1.0.0.1.
    3. 
          
  3. Set Preferred DNS encryption to Encrypted only (DNS over HTTPS).
    4. 
          
  4. Paste the DoH URL in the box that appears, e.g. https://dns.google/dns-query.
    5. 
        

      

    


    

      🍏 macOS — system DNS or DoH app
      

        
    
          
  1. System Settings → Network → your interface → Details… → DNS.
    2. 
          
  2. Add 1.1.1.1 and 1.0.0.1 (or the provider's IPv4 pair).
    3. 
          
  3. For encrypted DNS, install a DoH profile (DNSecure / Cloudflare 1.1.1.1 app) and paste the DoH URL.
    4. 
        

      

    


    

      🐧 Linux — systemd-resolved or stubby
      

        
systemd-resolved drop-in (/etc/systemd/resolved.conf.d/dns.conf):

        
[Resolve]
DNS=9.9.9.9#dns.quad9.net 149.112.112.112#dns.quad9.net
DNSOverTLS=yes
DNSSEC=allow-downgrade

        
Then sudo systemctl restart systemd-resolved and check with resolvectl status.

        
For DoH only, run dnscrypt-proxy or cloudflared and point /etc/resolv.conf at it.

      

    


    

      🌐 Chrome / Edge / Brave / Firefox — Secure DNS
      

        
    
          
  1. Chrome/Edge/Brave: Settings → Privacy and security → Security → Use secure DNS → Custom.
    2. 
          
  2. Paste a DoH URL, e.g. https://dns.google/dns-query or https://dns.adguard-dns.com/dns-query.
    3. 
          
  3. Firefox: Settings → Privacy & Security → DNS over HTTPS → Increased Protection → Custom.
    4. 
        

      

    


    

      📶 Router / whole home network
      

        
    
          
  1. AdGuard Home (recommended): set Upstream DNS to https://dns.adguard-dns.com/dns-query or tls://dns.quad9.net.
    2. 
          
  2. OpenWrt: install stubby, set the upstream to a DoT hostname, point DHCP DNS at the router.
    3. 
          
  3. Stock router: set DNS to the provider's IPv4 pair (e.g. 94.140.14.14 / 94.140.15.15). Encryption is router→upstream only.
    4. 
          
  4. For Reels/Shorts on the whole network, use AdGuard Home's DNS rewrites only for whole apps — paths cannot be blocked. Add the ShortsGuard blocklists for app-level blocks.
    5. 
        

      

    


    

      ❓ Why is there no DNS that blocks Reels/Shorts but keeps the app?
      

        
Because DNS answers “which IP serves facebook.com?” — it never sees the path. facebook.com/reel/123, youtube.com/shorts/abc and instagram.com/reels/xyz resolve to the exact same servers as the normal feed. Blocking fbcdn.net, cdninstagram.com or googlevideo.com would also break every photo, story, normal video and Messenger attachment.

        
That is why ShortsGuard is a page-level guard (userscript / extension / cosmetic rules). It hides the surfaces and rewrites the URLs while the resolver keeps doing what DNS is good at: ads, malware, adult content, and whole-app blocks.

      

    


    

      🧪 How the live badges are produced
      

        
scripts/check_health.py opens a TLS connection on port 853 and sends a real example.com/A query to every DoT endpoint, and POSTs an RFC 8484 query to every DoH URL. Results go to data/health.json and the site reads that snapshot.

        
A red dead badge means the endpoint did not answer when the snapshot was taken — it may come back. A partial badge usually means DoT works but DoH needs HTTP/2.
